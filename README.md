# OpenWrt VPN Controller для Home Assistant

![Integration icon](custom_components/openwrt_vpn/brand/icon.png)

Экспериментальная custom integration **0.2.2** для Home Assistant. Config/Options Flow, русский и английский интерфейс, пять платформ, независимые политики Manual/Auto для секций Podkop, метрики, диагностика и история.

**Добавлен экспериментальный нативный контроллер Podkop 0.7.23/0.7.24.** Он выполняет изменения UCI и вызывает штатный генератор Podkop; встроенная демонстрация также сохранена. Нативное применение и HTTPS-путь проверяются в изолированном OpenWrt 25.12.5 с sing-box 1.12.17. Управление на рабочем роутере по умолчанию выключено. Ограничения IPv6 и конкурентной записи LuCI описаны в [инструкции контроллера](docs/podkop-controller.ru.md).

Релиз **0.2.2** содержит интеграцию HA и отдельный пакет контроллера OpenWrt. Она показывает состояние VPN-интерфейсов до одобрения управления, исправляет выбор текущей политики и поддерживает [проверку динамического внешнего IPv4](docs/dynamic-egress.ru.md). Мониторинг настраивается на OpenWrt отдельно от HA; пустая конфигурация обнаруживает интерфейсы, но не измеряет доступность VPN. Ранее опубликованный релиз 0.2.0 сохраняется в [списке релизов](https://github.com/kostenkodm/hass_openwrt_control/releases).

## Установка через HACS

1. Откройте HACS → меню ⋮ → «Пользовательские репозитории».
2. Добавьте `https://github.com/kostenkodm/hass_openwrt_control`, тип **Integration**.
3. Откройте **OpenWrt VPN Controller (prototype)** и в диалоге загрузки выберите **v0.2.2**. Это предварительный релиз; при необходимости откройте выбор другой версии или показ предварительных версий. Обычный стабильный релиз 0.1.0 не содержит нативного контроллера Podkop.
4. Перезапустите Home Assistant.
5. «Настройки» → «Устройства и службы» → «Добавить интеграцию» → **OpenWrt VPN Controller (prototype)**. Если интеграция уже добавлена, повторно создавать её не нужно.

HACS доставляет компонент HA. Для управления реальным Podkop сначала установите отдельный контроллер OpenWrt по [инструкции](docs/podkop-controller.ru.md), затем выберите «Подключение к контроллеру». Demo позволяет познакомиться с интерфейсом без роутера. [Порядок добавления пользовательского репозитория](https://www.hacs.dev/docs/faq/custom_repositories/).

## Если HACS пишет custom_components/None/manifest.json

Это означает, что HACS не определил имя каталога интеграции. Ошибочный путь может сохраняться в записи репозитория, в том числе после неудачного чтения закрытого репозитория; принудительное обновление такой записи не всегда восстанавливает путь.

1. HACS → ⋮ → «Пользовательские репозитории»: удалите `kostenkodm/hass_openwrt_control` из этого списка.
2. Добавьте `https://github.com/kostenkodm/hass_openwrt_control` заново с типом **Integration**. Это создаёт новую запись и повторно определяет каталог.
3. Откройте интеграцию в HACS, выберите **v0.2.2**, скачайте и перезапустите HA.

Настоящий загрузчик HACS 2.0.5 проверен в отдельном локальном каталоге Home Assistant: свежее обнаружение определило `openwrt_vpn`, загрузка версии v0.2.0 установила все 24 файла. Сохранённый путь `custom_components/None` воспроизвёл указанную ошибку даже после принудительного обновления. Это проверка загрузчика и файлов; установка в HAOS пользователя остаётся отдельной проверкой.

## Установка 0.2.2 из архива

Архив содержит тот же компонент HA и подходит для ручной установки.

1. Откройте [список релизов](https://github.com/kostenkodm/hass_openwrt_control/releases) и выберите 0.2.2.
2. Скачайте **openwrt-vpn-ha-0.2.2.zip**. Скопируйте из него каталог `custom_components/openwrt_vpn` в `/config/custom_components/openwrt_vpn` вашего HAOS. При обновлении замените содержимое этого каталога, сохранив резервную копию прежней версии.
3. Перезапустите Home Assistant.
4. «Настройки» → «Устройства и службы» → «Добавить интеграцию» → **OpenWrt VPN Controller (prototype)**.
5. Для знакомства с интерфейсом выберите **«Демонстрационный режим»**. Для реальных секций сначала установите отдельный контроллер OpenWrt по [инструкции](docs/podkop-controller.ru.md), затем выберите **«Подключение к контроллеру»**.

Токен вашего HA и отдельный сервер для Demo не нужны. Минимальная заявленная версия Core — **2026.10.1**; проверка выполнялась с этой версией, установка в HAOS пользователя ещё не проверялась.

## Что смотреть после установки

Откройте устройство **OpenWrt VPN — Demo** в добавленной интеграции. Появятся 55 сущности: три секции `main`, `media`, `custom`, три VPN `vpn_a`, `vpn_b`, `vpn_c`, общие настройки и диагностика. Названия демонстрационных секций не означают, что такие секции найдены на целевом роутере.

1. У секции **main** выберите **vpn_b** в сущности политики. В начальном режиме `observe` предлагаемый VPN станет vpn_b, применённый останется vpn_a. Политики `media` и `custom` сохранятся.
2. В параметрах интеграции → «Общие параметры» выберите **control**. Теперь назначения применяются внутри симулятора.
3. Для автоматического выбора установите **main → Auto** и включите сущность **«Автоматический выбор VPN»**.
4. Параметры интеграции → **«Демонстрационные сценарии»** → **«vpn_a недоступен»**. main перейдёт на vpn_b после подтверждённых синтетических отказов. Ручные политики остальных секций сохранятся.
5. **«Все VPN недоступны»** сохраняет последнее назначение и включает тревогу. **«Восстановить все VPN»** возвращает доступность; обратное переключение учитывает время удержания, по умолчанию 600 секунд.
6. В версии 0.2.0 для каждого VPN есть кнопка **«Перезапустить …»**; в Demo она создаёт синтетическое событие. На OpenWrt перезапуск требует локального разрешения и проверки контроллера.
7. Посмотрите **«Недавние события»** и его атрибуты. Сценарий ошибки проверки позволяет проверить откат следующего применения.

Сущности можно добавить на свою панель штатными карточками HA. [Подробная инструкция](docs/prototype.ru.md) содержит пример проверки отката и описание хранения.

Демонстрация запускается внутри HA, слушает только loopback и останавливается вместе с HA. Её политики сохраняются после перезагрузки интеграции. Это режим знакомства с интерфейсом; нативный контроллер работает отдельной службой procd независимо от HA.

## Архитектура рабочего подключения

Home Assistant → **HTTPS ubus JSON-RPC с проверкой сервера** → автономный OpenWrt VPN Controller → UCI/Podkop.

Форма подключения подготовлена для ограниченного объекта `vpn.controller`. Интеграция разрешает команды встроенной демонстрации и нативному контроллеру `openwrt_ucode` с возможностью `policy_control`. Нативный режим `observe` сохраняет желаемые политики без переключения; `control` требует локального включения и проверок контроллера. Обычный ubus OpenWrt без специализированного контроллера этому протоколу не соответствует.

Отдельный RPC login и минимальный ACL; универсальные UCI, shell, управление службами и перезапуск сети Home Assistant не предоставляются. Защищённые интерфейсы определяются локальным списком на роутере и исключены из исходящих кандидатов. SSH предназначен для установки и резервной диагностики.

Исследованный reload Podkop 0.7.23 снимает перехват и перезапускает sing-box. Нативный адаптер сохраняет существующий перехват, формирует конфигурацию штатными функциями и обновляет только sing-box. Production-приёмка ещё требует проверки на ARM64 целевом роутере, полного покрытия IPv6 и решения остаточной гонки libuci с несогласованным конкурентным писателем.

## Для разработки

В WSL/Linux из корня проекта:

```sh
bash tools/bootstrap.sh
bash tools/run_tests.sh
work/venv-linux/bin/python -m tools.demo
work/venv-linux/bin/python -m tools.package_prototype
```

Все необходимые для HACS файлы находятся в `custom_components/openwrt_vpn/`, включая демонстрационный backend. Корневые `simulator/` и `tools/` нужны только для разработки и отдельного лабораторного сервера. Отчёты и архивы 0.2.2: `outputs/podkop-0.2.2/`; зависимости и приватные файлы стенда: `work/`, исключены из Git.
