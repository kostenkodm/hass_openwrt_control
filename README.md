# OpenWrt VPN Controller для Home Assistant

![Integration icon](custom_components/openwrt_vpn/brand/icon.png)

Custom integration **0.1.0** для установки через HACS. Config/Options Flow, русский и английский интерфейс, пять платформ, независимые политики Manual/Auto для секций Podkop, метрики, диагностика и история.

**В этой версии доступна встроенная демонстрация. Нативный контроллер OpenWrt ещё не реализован: управление реальным Podkop пока недоступно.** Все проверки, внешние IP и переключения демонстрации смоделированы. Защита от сетевых утечек симуляцией не подтверждается.

## Установка через HACS

Версия 0.1.0 публикуется в публичном репозитории `kostenkodm/hass_openwrt_control`. Добавьте его как пользовательский репозиторий HACS, тип Integration.

1. В HACS откройте ⋮ → «Пользовательские репозитории».
2. Добавьте `https://github.com/kostenkodm/hass_openwrt_control`, тип **Integration**.
3. Найдите **OpenWrt VPN Controller (prototype)** и скачайте интеграцию.
4. Перезапустите Home Assistant.
5. «Настройки» → «Устройства и службы» → «Добавить интеграцию» → **OpenWrt VPN Controller (prototype)**.
6. Выберите **«Демонстрационный режим»** и подтвердите создание.

Токен вашего HA, адрес роутера, SSH и отдельный сервер демонстрации не нужны. Минимальная заявленная версия Core — **2026.10.1**; проверка выполнялась с этой версией в WSL, установка в HAOS пользователя ещё не проверялась. Порядок добавления репозитория: [документация HACS](https://www.hacs.xyz/docs/faq/custom_repositories/).

## Что смотреть после установки

Откройте устройство **OpenWrt VPN — Demo** в добавленной интеграции. Появятся 52 сущности: три секции `main`, `media`, `custom`, три VPN `vpn_a`, `vpn_b`, `vpn_c`, общие настройки и диагностика. Названия демонстрационных секций не означают, что такие секции найдены на целевом роутере.

1. У секции **main** выберите **vpn_b** в сущности политики. В начальном режиме `observe` предлагаемый VPN станет vpn_b, применённый останется vpn_a. Политики `media` и `custom` сохранятся.
2. В параметрах интеграции → «Общие параметры» выберите **control**. Теперь назначения применяются внутри симулятора.
3. Для автоматического выбора установите **main → Auto** и включите сущность **«Автоматический выбор VPN»**.
4. Параметры интеграции → **«Демонстрационные сценарии»** → **«vpn_a недоступен»**. main перейдёт на vpn_b после подтверждённых синтетических отказов. Ручные политики остальных секций сохранятся.
5. **«Все VPN недоступны»** сохраняет последнее назначение и включает тревогу. **«Восстановить все VPN»** возвращает доступность; обратное переключение учитывает время удержания, по умолчанию 600 секунд.
6. Посмотрите **«Недавние события»** и его атрибуты. Сценарий ошибки проверки позволяет проверить откат следующего применения.

Сущности можно добавить на свою панель штатными карточками HA. [Подробная инструкция](docs/prototype.ru.md) содержит пример проверки отката и описание хранения.

Демонстрация запускается внутри HA, слушает только loopback и останавливается вместе с HA. Её политики сохраняются после перезагрузки интеграции. Это режим знакомства с интерфейсом; автономность будущего OpenWrt-контроллера от HA остаётся отдельным требованием.

## Архитектура рабочего подключения

Home Assistant → **HTTPS ubus JSON-RPC с проверкой сервера** → автономный OpenWrt VPN Controller → UCI/Podkop.

Форма подключения подготовлена для ограниченного объекта `vpn.controller`. Эта версия разрешает команды только симулятору; для другого backend доступно чтение совместимого API. Обычный ubus OpenWrt без специализированного контроллера этому протоколу не соответствует.

Отдельный RPC login и минимальный ACL; универсальные UCI, shell, управление службами и перезапуск сети Home Assistant не предоставляются. `inbound_vpn` исключён из исходящих кандидатов. SSH предназначен для установки и резервной диагностики.

Исследованный reload Podkop 0.7.23 снимает перехват и перезапускает sing-box. Для production нужны безопасное применение, реальная egress-проверка, согласование LuCI, транзакционный откат и стендовые проверки IPv4/IPv6 и `inbound_vpn`.

## Для разработки

Рабочая папка: `W:\dev\hass-openwrt`. В WSL/Linux:

```sh
cd /mnt/w/dev/hass-openwrt
bash tools/bootstrap.sh
bash tools/run_tests.sh
work/venv-linux/bin/python -m tools.demo
work/venv-linux/bin/python -m tools.package_prototype
```

Все необходимые для HACS файлы находятся в `custom_components/openwrt_vpn/`, включая демонстрационный backend. Корневые `simulator/` и `tools/` нужны только для разработки и отдельного лабораторного сервера. Отчёты и архивы: `outputs/prototype/`; зависимости и приватные файлы стенда: `work/`, исключены из Git.
