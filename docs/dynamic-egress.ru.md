# Мониторинг VPN с динамическим внешним IPv4

Контроллер 0.2.2 поддерживает локальный параметр `egress_mode: "dynamic"` внутри разрешённого VPN. В этом режиме `egress_ips` не требуется. Пример записи: `"vpn_a": {"approved": true, "egress_mode": "dynamic"}`. Не включайте защищённые, входящие, управляющие, LAN/WAN или исходные интерфейсы Podkop в список разрешённых исходящих VPN.

Для общего списка и каждой секции нужны минимум три проверочных ресурса разных операторов. Как минимум два должны быть HTTPS-сервисами с `egress=true`, возвращающими только внешний IPv4 текстом. Используйте разные службы и домены; контроллер различает имена хостов, но не может определить их владельцев. Адрес назначения фиксируется локально в `ip`; SNI, имя сертификата и доверенный CA проверяются. Прототип не обновляет IP проверочных сервисов автоматически: при смене их инфраструктуры ресурсы надо обновить локально.

Выход подтверждается при согласии минимум двух разных HTTPS-хостов. Успешные ответы с разными внешними IP отвергаются. Частные, локальные, тестовые, multicast и зарезервированные диапазоны не принимаются. Реализация консервативно исключает специальные диапазоны [IANA](https://www.iana.org/assignments/iana-ipv4-special-registry/). Запросы выполняются с [curl `--interface if!`](https://curl.se/docs/manpage.html#--interface), привязанным к реальному устройству разрешённого VPN; имя устройства должно совпадать с его netifd-интерфейсом. Доступность WAN не заменяет отказавший VPN.

При экспериментальном применении Podkop проверяется фактическая привязка исходящего маршрута sing-box. HTTPS-пробы через локальный SOCKS-вход секции должны дать тот же внешний IPv4, что и свежие пробы через выбранный VPN, с согласием минимум двух хостов для каждого пути. Расхождение, смена IP между этими пробами или недоступность пути приводят к отказу проверки и транзакционному откату. Общие ограничения control, защита исходных конфигураций и ACL сохранены. Динамический IP не отменяет локального разрешения на изменение Podkop.

Начинать следует с наблюдения: `control_enabled=false`, `restart_enabled=false`, автоматика выключена. Разрешение VPN включает мониторинг и выбор желаемой политики в HA, но в observe не меняет назначения Podkop. HA 0.2.2 отдельно показывает, поднят ли интерфейс; это не подтверждение работоспособности VPN. Последний handshake нативным контроллером пока не реализован.

Проверки стенда охватывают смену внешнего IP, противоречивые и некорректные ответы, отказ VPN при доступном WAN, реальное применение через sing-box, откат и сохранность защищённых конфигураций. Стенд использует изолированные veth-интерфейсы и контролируемые HTTPS-сервисы; это не production-проверка ARM/AWG, offload, IPv6 и всех видов трафика.
